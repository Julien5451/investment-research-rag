# 简历与面试材料

项目名称：**投研文档检索问答与证据评测系统**。

技术栈：Python 3.11、FastAPI、LangChain、Chroma、PyMuPDF、Streamlit、OpenAI-compatible Chat/Embedding API。运行环境为 WSL Ubuntu，本地单进程演示。

## 三条简历要点

- 基于 FastAPI、LangChain 与 Chroma 完成企业年报 RAG 系统，支持 PDF 按页解析、持久化检索、来源页码与原文引用、证据不足拒答，并提供 Streamlit 上传和问答演示。
- 建立证据 requirement/多 chunk 组合标注与离线诊断，比较 Dense、BM25+RRF 的 Top-3/Top-5；在同一 24 题开发集上验证混合检索未提高证据召回，保留较简单的 Dense 路径。
- 在冻结模型、题集与评分口径下完成三组真实 API 配对评测，同一 24 题开发集总体正确率为 70.83% → 83.33%；选定实现后完成另一公司 12 题 holdout，取得 10/12 正确，并保留逐题回答、引用及失败记录。

第三条的三组执行均为 baseline 17/24、selected 20/24。干预是 Top-5 和通用完整回答/表格摘录提示的组合，实际平均上下文多约 60.3%，不能声称已证明单独某个改动的因果收益。开发集 selected pooled P95 为 2.905 秒；评测由代理辅助逐题复核，没有独立人工盲评。

独立公司 Costco holdout 没有参与参数或 prompt 选择：baseline 8/12、selected 10/12，后者可回答题为 7/9，另有 3 条正确拒答；selected P95 为 4.251 秒，baseline 为 3.066 秒。它只有单次执行且题数很小，不能据此声称广泛可推广或性能显著提升。最终 **224 项离线测试通过**，Ruff lint 与格式检查通过，完整证据见 [Phase 3 结果](phase3_results.md)。

## 可以展开的项目介绍

我做的是一个面向企业年报的本地 RAG 问答系统。上传 PDF 后，按物理页提取文本，在单页内切块并生成向量，保存到 Chroma。提问时做语义检索，只把筛选后的证据交给 chat 模型。模型的来源 ID 和原文摘录要经过后端校验；证据不足或引用无法验证时明确拒答。

我把页面演示、检索诊断和真实模型评测分开。Streamlit 经 HTTP 调用 FastAPI；检索实验复用固定 corpus 和同一批 query vectors；真实 A/B 使用冻结的 baseline 与候选 QA，保存每题检索、原始生成、最终引用、失败原因和耗时，按相同标准逐题复核。不同公司的 holdout 不参与参数或 prompt 选择。

一个关键发现是“正确页被召回”不代表“答案证据被召回”。财务行可能没有年份/单位表头；同一个事实也可能出现在另一页。为此我增加独立 sidecar 的证据组合标签，把 Page Recall、Evidence Recall 和答案正确率分开报告。BM25/RRF 的实测没有增加证据召回，因此没有把它放入默认在线路径。

对引用问题也先确认原因：有些是模型把表格改写成不存在的引文，有些其实是缺失总额后错误求部分和。单纯修补 quote 可能让错误 claim 更容易通过；本阶段保留原文验证，仅试验通用的完整回答和连续表格摘录提示，没有默认加第二次 LLM 调用。

## 面试问答要点

| 问题 | 回答要点 |
| --- | --- |
| 系统是否微调了金融模型？ | 没有。本阶段重点是检索、证据边界、引用校验和评测，没有训练模型 |
| 为什么需要三类指标？ | 页召回只看来源位置；证据召回检查所需事实及其上下文；答案准确率还需判断最终表达是否正确、完整 |
| Evidence Recall 如何避免只匹配答案数字？ | 明确标注支持的 requirement 与等价组合，校验 chunk 身份/原文哈希/摘录，财务行必要时同时要求单位和年份表头 |
| 为什么最后没有默认用 hybrid？ | 四组比较中 BM25/RRF 没有增加已核验证据召回，却增加启动/排序成本；保留负结果和可选实验代码，默认用简单 Dense |
| Top-5 比 Top-3 高能否证明检索算法更好？ | 不能，它增加可用 chunks 和实际上下文；本轮 Dense 平均上下文约多 60.3%，必须把代价一起报告 |
| 引用都能匹配原文是否就没有幻觉？ | 不能。真实引文也可能被错误解释；需区分 returned-citation provenance 与 claim 是否被证据推出 |
| 为什么不加一次自动引用修复？ | 当总额证据缺失时，修复为真实组成行也可能给错误总额配上引文；没有可靠语义 eligibility 判定，就保留拒答 |
| 多次运行是否等于更大的测试集？ | 不是。重复的是同一批开发题，用于观察模型波动；不能当成新增独立样本或统计显著性证据 |
| holdout 是否经过独立人工盲评？ | 不应这样声称。它来自不同公司且不用于调参，参考答案经原文核验，结果仍由代理辅助复核 |
| 当前工程边界？ | 本地单 worker、同步入库、字符分块；没有 OCR、生产多租户、认证或部署能力 |
